# 6. Hands-on Labs

Six labs, from "just run it" to "extend the system". Each has a goal, steps, and a *check yourself*
section. Hints and solution sketches are at the bottom.

---

## Lab 1 — Run it and explore (20 min)

**Goal:** see the whole system work end to end.

1. `mvn clean package` — watch for `Tests run: 17, Failures: 0`.
2. Terminal A: `java -jar target/data-connector-api.jar`
3. Terminal B:
   ```bash
   CP=target/data-connector-api.jar; MAIN=com.example.dataconnector.client.DataConnectorClient
   java -cp $CP $MAIN
   java -cp $CP $MAIN schema crm-files customers
   java -cp $CP $MAIN read sales-db orders --where is_shipped=false
   java -cp $CP $MAIN read crm-files nope
   ```
4. Look at Terminal A's log lines after each command.

**Check yourself**
- What status code did the last command produce? Where in the code is it created?
- Which columns of `customers` are `nullable`, and why? (Look at `data/csv/customers.csv`.)

## Lab 2 — Same server, a different language (20 min)

**Goal:** prove the API is language-independent.

1. Follow README step 4 to set up Python and run `./generate.sh`.
2. Open `python/generated/dataconnector/v1/data_connector_pb2_grpc.py`. Find `DataConnectorServiceStub`.
   Compare it with the Java `DataConnectorServiceGrpc` — same four methods.
3. Run `python -m dataconnector_client` and the Java demo. Compare outputs.
4. In a Python REPL:
   ```python
   from dataconnector_client.client import DataConnectorClient
   c = DataConnectorClient()
   dec = c.decoder("sales-db", "orders")
   print(dec.message_class, dec.field_names)
   ```

**Check yourself**
- `dec.message_class` was never written by anyone or generated by `protoc`. Where did it come from?

## Lab 3 — Look at the bytes (25 min)

**Goal:** understand the wire format.

```python
from dataconnector_client.client import DataConnectorClient
c = DataConnectorClient()
dec = c.decoder("crm-files", "customers")
row = dec.message_class(customer_id=1, name="Ava")
b = row.SerializeToString()
print(b.hex(" "))      # 08 01 12 03 41 76 61
```

1. Decode each byte by hand using the table in [chapter 2.3](02-core-concepts.md#the-binary-format--lets-decode-real-bytes).
2. Set `customer_id=300`. Predict the bytes before printing. (Hint: varints use 7 bits per byte, with
   the high bit meaning "more bytes follow". 300 = `0b1_0010_1100`.)
3. Compare `len(b)` with `len(json.dumps(dec.to_dict(row)))`.

## Lab 4 — Write your own connector (60–90 min)

**Goal:** add a new kind of data source without changing the API or any client.

Build an **`InMemoryConnector`** that serves one dataset, `planets`, from a hard-coded list:

| name | moons | has_rings | distance_au |
|------|-------|-----------|-------------|
| Mercury | 0 | false | 0.39 |
| Earth | 1 | false | 1.0 |
| Saturn | 146 | true | 9.5 |

Steps:

1. Create `src/main/java/com/example/dataconnector/connector/InMemoryConnector.java` implementing
   `DataConnector`.
2. Return a `TableSchema` with four `Column`s.
3. `read()` returns `rows.stream()`.
4. Add `case "memory" -> new InMemoryConnector(id);` in `ConnectorFactory.create`.
5. Add `{"id": "space", "type": "memory"}` to `config/connectors.json`.
6. Restart the server; run `python -m dataconnector_client read space planets --where has_rings=true`.

**Check yourself**
- How many files did you change? (Should be 2 Java files + 1 config file.) Did you touch the `.proto`
  or the Python client? (You shouldn't have!)
- Add a test to `ConnectorsTest`.

## Lab 5 — Make the database do the filtering (advanced, 60 min)

Right now `RowFilter` filters **in Java** after reading every row — even from SQL. Real systems
"push down" filters into the source.

1. Add an optional method to `DataConnector`:
   `default Stream<Map<String,Object>> read(String dataset, List<Filter> filters) { return read(dataset); }`
2. Override it in `JdbcConnector` to build `SELECT * FROM "ORDERS" WHERE "AMOUNT" > ?` using a
   `PreparedStatement` (**never** concatenate user values into SQL!).
3. Call it from the service. Keep the Java filter too — it's harmless and acts as a safety net.

**Check yourself** — why does using `?` placeholders prevent SQL injection?

## Lab 6 — Add an RPC (advanced, 45 min)

Add `rpc CountRows(ReadDataRequest) returns (CountRowsResponse);` that returns how many rows match.

1. Edit the `.proto` (add the RPC and a `CountRowsResponse { int64 count = 1; }`).
2. `mvn compile` — notice the new abstract method appears in `ImplBase`.
3. Implement `countRows` in the service (reuse the filter code).
4. Re-run `./generate.sh` and add `count()` to the Python client.

**Check yourself** — an old client generated *before* your change still works against the new server.
Why? (Hint: what does a server do with RPC names a client never calls? What would happen if you had
*renumbered* existing fields instead?)

<details>
<summary>Lab 3</summary>

300 → varint `ac 02` (low 7 bits `0101100` + continuation bit = `0xAC`, then `0000010` = `0x02`), so
the message starts `08 ac 02`.
</details>

<details>
<summary>Lab 4 skeleton</summary>

```java
public final class InMemoryConnector implements DataConnector {
  private final String id;
  public InMemoryConnector(String id) { this.id = id; }
  public String id() { return id; }
  public String type() { return "memory"; }
  public String description() { return "Hard-coded demo data"; }
  public List<String> listDatasets() { return List.of("planets"); }

  public TableSchema schema(String dataset) {
    if (!dataset.equals("planets")) throw new DatasetNotFoundException(id, dataset);
    return new TableSchema(id, dataset, List.of(
        new Column("name", ColumnType.COLUMN_TYPE_STRING, false),
        new Column("moons", ColumnType.COLUMN_TYPE_INT64, false),
        new Column("has_rings", ColumnType.COLUMN_TYPE_BOOL, false),
        new Column("distance_au", ColumnType.COLUMN_TYPE_DOUBLE, false)));
  }

  public Stream<Map<String, Object>> read(String dataset) {
    schema(dataset); // validates the name
    return Stream.of(
        Map.of("name", "Mercury", "moons", 0L, "has_rings", false, "distance_au", 0.39),
        Map.of("name", "Earth", "moons", 1L, "has_rings", false, "distance_au", 1.0),
        Map.of("name", "Saturn", "moons", 146L, "has_rings", true, "distance_au", 9.5));
  }
}
```
</details>

<details>
<summary>Lab 6</summary>

Adding RPCs and adding fields with *new* numbers is backward compatible: old clients simply never call
the new RPC, and old parsers skip unknown field numbers. Renumbering would make old clients interpret
bytes as the wrong fields — that's why field numbers are permanent.
</details>
